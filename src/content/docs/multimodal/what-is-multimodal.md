## 多模态建模需要解决什么

文本模型只能读文字，但真实世界的信息并不只以文字存在：截图、表格、照片、语音、视频、传感器数据都可能是任务输入。多模态大模型要解决的就是如何让模型同时理解和生成多种形式的信息。

## 从多种输入到共同任务

多模态大模型不是简单“把图片丢给语言模型”。它通常需要一个视觉或音频编码器，把非文本输入转成模型能处理的向量，再通过投影层、跨模态注意力或统一 token 序列接入语言模型。

常见能力包括图像问答、OCR 理解、图文检索、视觉推理、视频摘要、语音对话和屏幕操作。不同能力背后的数据、模型结构和评测方式差别很大。

## 模态编码与表示空间

以图像理解为例，系统一般包含三部分：视觉编码器、跨模态对齐模块、语言模型。视觉编码器把图片切成 patch 并提取特征；对齐模块把视觉特征映射到语言模型可接收的空间；语言模型再根据图像特征和文本问题生成答案。

CLIP 代表的是图文对齐思路：让图片和文本描述在同一向量空间中靠近。LLaVA 这类模型则把视觉特征接入大语言模型，让模型能围绕图像进行对话。它们解决的问题不同，不能简单混为一谈。

## 融合结构怎样影响能力

多模态系统最怕输入质量不可控。图片分辨率、裁剪方式、文字清晰度、表格结构、视频抽帧策略都会影响模型表现。一个看似“模型看错了”的问题，可能只是截图压缩太严重或关键区域没被送进上下文。

评测时也要分任务拆开：OCR 是否识别对？物体定位是否准确？模型有没有读懂图表关系？是否在没有证据时猜测？多模态幻觉通常比纯文本更隐蔽，因为用户未必会逐像素核对。

## 图表读取的应用示例

```txt
任务：分析一张销售报表截图。
输入：截图 + 用户问题。
视觉编码器：提取表格区域、文字和布局特征。
语言模型：结合问题生成解释。
输出：关键指标、异常点、可能原因。
验证：与原始表格数据或人工标注比对。
```

如果这个场景要求高准确率，最好接入原始表格数据，而不是只依赖截图理解。

## 图像是怎样进入语言模型的

主流视觉语言模型常先使用视觉编码器把图片转换成特征，再使用一个投影模块将其映射到语言模型的表示空间。视觉特征可以表示为若干 Patch Token，也可以经压缩与池化后变成更少的视觉 Token。

若一张图片被划分为 P 个 Patch，视觉编码器输出维度 d_v，经投影到语言模型维度 d_l，最基本的线性投影写为：

$$
H_{\mathrm{visual}}=F_{\mathrm{image}}(I)W_P,\qquad
W_P\in\mathbb R^{d_v\times d_l}.
$$

普通写法：visual_tokens = image_encoder(image) @ projection_matrix。

进入语言模型之前，需要决定视觉 Token 插入到文本序列中的位置、使用何种位置表示，以及是否保留分辨率和局部结构。多图、视频或高分辨率输入会使视觉 Token 数量显著增加，从而消耗上下文预算。

## CLIP 与生成式 VLM 为什么不一样

CLIP 的主要目标是把图像和文本映射到能够比较相似度的共享空间。它在批内正负样本间进行对比学习，常用于零样本分类和图文检索，不要求根据图片自动生成段落。

生成式视觉语言模型则希望依据视觉和文本上下文预测输出 Token。即便它使用 CLIP 一类视觉编码器，训练损失和任务形态也与纯对比学习不同。**表征对齐**解决“图文是否相关”，**生成式理解**进一步尝试回答“图像中的信息如何被组织为语言”。

## 两个需要分别测量的错误

OCR 错误通常来自局部字符分辨率、模糊、字体和裁剪；图表推理错误可能在文字识别正确后仍然发生，例如把横轴对数刻度当线性刻度，或者混淆统计量的单位。

构造一个评测集时，可将任务拆为文字提取、对象定位、数值读取、关系推断和多步推理。对同一张图像，如果先提供人工转录文本后准确率明显改善，说明瓶颈可能更多来自视觉读取而不是语言推断。

| 子任务 | 核心输入 | 主要验证方式 |
|---|---|---|
| OCR | 图片文字区域 | 字符错误率 / 完整字段命中 |
| 图文检索 | 图像与候选描述 | Recall@k |
| 图表数值 | 坐标轴与数据标记 | 数值误差、单位正确性 |
| 视觉问答 | 图像与问题 | 任务准确率、证据一致性 |


## 多模态能力的实际边界

第一，把“能看图”当成“能可靠读图”。图像描述、文字识别、图表计算、空间推理是不同能力。

第二，忽略预处理。裁剪、缩放、抽帧、去噪和版面解析经常决定上限。

第三，用开放问答评估所有能力。多模态系统需要针对 OCR、定位、计数、图表理解等子任务分别测。

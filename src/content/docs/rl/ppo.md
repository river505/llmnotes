## 本文解决什么问题

PPO 经常出现在 RLHF 文章里，但如果只记“近端策略优化”这几个字，很难理解它为什么受欢迎。本文从一个问题出发：更新策略时，怎样让模型朝更高奖励前进，同时不要一步迈太大导致崩掉？

## 核心结论

PPO 是一种策略梯度算法，核心思想是限制新策略和旧策略的差距。它允许策略变好，但不希望每次更新都把行为分布改得过猛。常见做法是使用 clipped objective，把策略概率比值裁剪在一个范围内。

在 RLHF 中，PPO 通常用于让语言模型根据奖励模型的反馈调整输出偏好，同时用 KL 惩罚限制它不要偏离原始模型太远。

## 概念解释

策略梯度会提高带来好结果的动作概率，降低带来坏结果的动作概率。问题是神经网络一次更新可能影响大量状态下的行为，如果步子太大，旧数据对新策略就不再可靠，训练会震荡。

PPO 用概率比值衡量新旧策略变化：

```txt
ratio = pi_new(action | state) / pi_old(action | state)
```

如果 ratio 太大或太小，说明新策略对同一动作的偏好变化过猛。clipping 会把这个变化限制住，让优化更稳。

## 数学/工程直觉

PPO 还会用优势函数 advantage 来判断某个动作比平均水平好多少。优势为正，就倾向提高该动作概率；优势为负，就倾向降低它。但这种调整会被 clip 限制，避免一次更新过度相信当前 batch。

在大模型对齐里，奖励模型可能偏、训练样本可能窄，所以“不要离原模型太远”很重要。KL 惩罚就是在提醒模型：可以朝人类偏好移动，但不要忘掉原本的语言能力和基本安全边界。

## 简化流程

```txt
1. 用当前策略模型生成回答
2. 奖励模型给回答打分
3. 估计每个 token 或回答的 advantage
4. 用 PPO objective 更新策略模型
5. 加入 KL 惩罚，限制偏离参考模型
6. 重复采样、评分、更新
```

真实训练还会涉及 value model、batch 构造、归一化、长度惩罚和安全过滤。

## 常见误区

第一，把 PPO 当成 RLHF 的全部。RLHF 还包括监督微调、偏好数据、奖励模型训练和安全评测。

第二，以为奖励越高越好。奖励模型不是绝对真理，模型可能学会迎合奖励漏洞。

第三，忽略 KL 约束。没有约束时，策略可能为了奖励牺牲流畅性、事实性或安全性。

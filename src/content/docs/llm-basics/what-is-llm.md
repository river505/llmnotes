## 本文解决什么问题

刚开始学习大模型时，最容易把几个词混在一起：大模型、基础模型、语言模型、LLM、生成式 AI。它们确实有交集，但不是同一个层级的概念。本文先把这张地图画清楚，后面再看 Transformer、RAG、Agent 或 RLHF 时，就不会每遇到一个新名词都重新迷路。

## 核心结论

大模型通常指参数规模、训练数据规模和通用能力都比较大的模型；基础模型强调它先在大规模数据上预训练，再迁移到很多下游任务；LLM 则是以文本为主要输入输出形态的基础模型。三者的关系可以简单理解为：

- 大模型是规模和能力层面的说法。
- 基础模型是训练范式和复用方式层面的说法。
- LLM 是语言模态上的一类基础模型。

所以，LLM 不只是“会聊天的程序”。它本质上是在大量文本和代码中学习语言模式、知识关联和推理痕迹，再根据上下文预测接下来最合理的 token。

## 概念解释

传统 NLP 系统往往为每个任务单独设计：情感分类有一个模型，机器翻译有一个模型，问答系统又是一套流程。LLM 的变化在于，它把大量任务统一成“给定上下文，生成后续文本”的形式。分类、改写、摘要、代码生成、工具调用，表面不同，底层都可以被包装成条件生成。

基础模型的关键价值是“先学通用表示，再做任务适配”。预训练阶段让模型接触海量语料，学习语言结构、事实关联、代码模式和一定的世界知识；指令微调和偏好对齐阶段再让模型更像一个可协作的助手。真实产品里，还会叠加检索、工具、缓存、权限、审计和评测系统。

## 数学/工程直觉

从数学上看，LLM 做的是条件概率建模：给定前面的 token 序列，预测下一个 token 的分布。模型越大、数据越丰富、训练越充分，它捕捉到的上下文模式就越细。这个目标看起来简单，却能涌现出翻译、摘要、代码补全和多步推理等能力，因为这些任务都可以拆成一连串 token 选择。

从工程上看，LLM 不是单独上线的“一个模型文件”。一个可用系统至少要考虑上下文窗口、推理延迟、成本、幻觉、数据安全、提示词版本、评测集和失败兜底。模型能力决定上限，系统设计决定稳定性。

## 一个具体例子

```txt
用户：把这段会议纪要整理成待办事项。
系统：提供会议原文、输出格式、责任人字段和截止日期规则。
LLM：根据上下文生成结构化待办列表。
工程系统：检查字段完整性，保存到任务系统，记录输入输出用于回归评测。
```

这个例子里，LLM 负责语言理解和生成，外层系统负责约束、集成和验证。把两者分开看，很多“模型不稳定”的问题其实会变成可定位的工程问题。

## 训练和生成的时间维度为什么不同

自回归语言模型按概率链式法则把整段文本分解为条件概率：

$$
p_\theta(x_{1:T})=\prod_{t=1}^{T}p_\theta(x_t\mid x_{<t}).
$$

普通写法：sequence_prob = product(next_token_prob(token_t | previous_tokens))。

训练时，完整文本已经存在。通过因果掩码，模型可以在一次前向计算中同时估计多个位置的目标 Token 概率；生成时，未来 Token 尚不存在，必须先选择当前位置的输出，再接着计算下一位置。这里的差异解释了为何 Transformer 可以高度并行训练，自回归推理却经常受到逐 Token 执行的约束。

考虑上下文“今天的天气很”，模型并不是先在内部写出整句回复，再依次输出汉字。它计算下一个 Token 的词表 Logits，经 Softmax 和采样策略选择一个 Token，再将新 Token 加入序列。模型可能有成千上万个候选 Token，最后显示的字符边界不一定等于 Token 边界。

## 一个容易混淆的工程流程

从用户输入到最终可读的回复，至少经过 Tokenizer、Embedding、Transformer Block、词表投影和解码器。输入与输出可以按下图理解：

~~~text
文本输入
   ↓ Tokenizer / Chat Template
Token IDs [B, L]
   ↓ Embedding
Hidden states [B, L, D]
   ↓ Transformer blocks
Last-position hidden state [B, D]
   ↓ Output projection + Softmax
Next-token distribution [B, V]
   ↓ Sampler
一个新 Token → 追加到历史 → 下一轮
~~~

B 是批次大小，L 是上下文长度，D 是隐藏维度，V 是词表大小。需要注意的是，这是一条简化的推理链路；工程实现可能融合 Softmax 与采样、复用 KV Cache，并使用量化和批处理减少开销。

## 如何观察模型真正的行为

对固定提示词，分别使用 Greedy、Temperature=0.7 与 Top-p=0.9 生成多个样本。记录 Token 序列、Logits 或对数概率、生成长度和运行延迟。这样的实验能够将“模型预测哪些 Token”和“采样器最终选了哪个 Token”分开。

如果输出变化很大，首先排查采样与随机种子；如果特定事实持续错误，则应检查模型知识、上下文和检索证据。通过实验拆开模型分布、采样策略和外部信息来源，比将所有输出问题归结为“模型不理解”更有解释力。


## 常见误区

第一，把参数量等同于能力。参数量很重要，但数据质量、训练方法、对齐方式、推理策略和工具链同样会影响最终效果。

第二，把 LLM 当数据库。模型可以记住大量模式和事实，但它不是可靠的事实存储；需要准确、可追溯的信息时，应优先接入检索或结构化数据源。

第三，只讨论模型，不讨论场景。同一个模型在客服、代码、投研、教育里的风险边界完全不同，评测方式也不同。

## 怎样建立可复现的学习路径

大模型学习资料很多，但初学者最容易遇到的问题不是资料不够，而是不知道先后顺序。本文给出一条适合零基础到项目入门的路线：先建立概念地图，再理解模型机制，然后做 RAG/Agent 项目，最后准备面试和论文精读。

## 阶段目标与可验证产物

这条路线的目标不是让你一开始就训练大模型，而是让你具备三种能力：

1. 能解释核心概念：token、attention、Transformer、RAG、Agent、RLHF。
2. 能看懂基础代码和系统流程：数据如何进入模型，结果如何评估。
3. 能完成一个小型项目：例如知识库问答、文档助手或 Code Agent。

如果目标是求职，还要能把项目讲清楚：背景、方案、指标、失败案例和改进方向。

## 第一阶段：大模型基础

先理解 LLM 是什么、它和传统 NLP 的区别、token 如何进入模型、上下文窗口和推理参数如何影响输出。这个阶段不用急着看复杂论文，重点是建立正确直觉。

建议阅读：

- 什么是大模型、基础模型与 LLM
- Token、Tokenizer 与词表
- 用 4 个 Token 看懂 Attention

学完后，你应该能解释：为什么模型处理的是 token，为什么 attention 能让 token 之间交换信息，为什么 LLM 不是可靠数据库。

## 第二阶段：Transformer 机制

这一阶段重点看 Attention、Multi-Head、位置编码、残差连接、LayerNorm、前馈网络。不要只看模型图，要能顺着数据流讲一遍：输入 token 如何变成 embedding，如何经过多层计算，最后如何生成下一个 token。

建议阅读：

- 用 4 个 Token 看懂 Attention
- 为什么要除以 sqrt(d_k)
- Attention Is All You Need 精读

学到这里，不需要手写完整训练框架，但最好能用小矩阵解释 attention 的计算过程。

## 第三阶段：RAG 工程

RAG 是最适合入门落地的大模型项目之一。它不要求训练模型，但会涉及文档解析、切分、向量检索、重排、prompt、引用和评测，能很好地训练工程直觉。

建议先做一个小型知识库问答系统：准备 20 到 50 篇文档，完成解析入库，设计 30 个测试问题，记录检索命中和最终回答质量。

重点不是界面多漂亮，而是能回答：答案错时，是没检索到证据，还是模型没有正确使用证据？

## 第四阶段：Agent 与工具调用

理解 RAG 后，可以继续做 Agent。Agent 的重点是多步任务、工具调用、状态管理和安全边界。建议从低风险工具开始，比如文件搜索、只读数据库查询、网页检索，再逐步加入写操作和人工确认。

一个适合练手的项目是 Code Agent：读取报错日志，定位相关代码，提出修改建议，运行测试，并生成变更摘要。

## 第五阶段：RLHF 与评测

RLHF 不建议作为第一阶段重点，但需要知道它在大模型对齐中的位置。先理解强化学习的 state、action、reward、policy，再看 PPO 和奖励模型。重点不是背公式，而是理解为什么奖励设计、KL 约束和评测很重要。

同时要补评测意识。大模型项目如果没有评测集，很容易只凭几个演示样例判断效果。至少要准备固定问题集、失败案例分类和版本对比记录。

## 学习节奏

一个可执行的 6 周安排：

```txt
第 1 周：LLM、token、上下文、推理参数
第 2 周：Attention、Transformer、原始论文导读
第 3 周：RAG 基础链路和文档切分
第 4 周：完成一个小型 RAG 项目并做评测
第 5 周：Agent、ReAct、工具调用和权限控制
第 6 周：整理项目、补面试题、复盘失败案例
```

每天不需要追很多新名词，但要保证每周有一个可复述、可运行或可验证的产出。

## 阶段完成标准：不要只看阅读数量

阅读路线最容易出现的偏差，是把“读过一篇文章”当成“掌握了这项技术”。更可靠的方式是为每个阶段设计一个小型可检查产物。

| 阶段 | 必须完成的产物 | 最小验收方式 |
|---|---|---|
| Token 与输入表示 | 一份分词统计脚本 | 能解释不同文本的 Token 长度差异 |
| Attention | 一段 NumPy Attention | 与参考实现的形状和数值一致 |
| Transformer | 一张完整数据流图 | 能区分 Self/Cross-Attention 和 Mask |
| RAG | 固定测试集与检索报告 | 计算 Recall@k 并定位失败问题 |
| Agent | 一个受控工具执行循环 | 运行成功与失败分支的集成测试 |
| 论文阅读 | 一篇公式与方法复现记录 | 讲清方法假设与对照实验 |

这些产物可以是本地小脚本，不要求制作成完整网页或复杂产品。重点是训练自己从概念走到代码，再通过测试返回机制理解。

## 一次完整的 Attention 学习练习

从四个固定 Token Embedding 开始，先手算一行 QKᵀ 的结果；再写 NumPy 程序得到全部矩阵；然后加因果 Mask 并检查上三角为零；最后比较不同维度下缩放分数的范围。

做完之后，至少应该能回答：为什么 QKᵀ 的形状是 L×L，Softmax 对哪个维度执行，V 的加权聚合改变了什么，以及 Decoder 中的位置编码和因果掩码分别负责什么。

相比看完五篇文章却不能复现一次前向计算，这种学习方式更容易建立稳定的算法基础。

## 什么时候开始读论文

不必等到所有基础课结束。只要已经能解释 Attention 的形状、因果 Mask 和位置表示，就可以开始读原始 Transformer 论文。遇到不理解的模块再回到对应文档，而不是把技术阅读严格排成单向流水线。

论文阅读应记下一个可验证问题，例如“取消循环后为何能在时间维度并行”；然后对照结构图、公式与实验，判断作者提供了什么证据。这样能避免停留在转述摘要的层面。


## 三种低效学习方式

第一，上来就追最新模型。模型更新很快，但 token、attention、检索、评测这些基础不会过时。

第二，只看文章不做项目。大模型工程的很多问题只有接入真实文档、真实 API、真实测试时才会出现。

第三，只准备标准答案。面试和项目汇报更看重你如何排查问题、权衡成本和承认边界。

## 从基础文档开始

先从本站“大模型基础”和“Transformer 专题”开始，再进入 RAG 和 Agent。等你能做出一个可评测的小项目后，再读论文精读和面试题，效率会高很多。

## 技术面试需要证明哪种能力

大模型面试很少只考一个孤立名词。更常见的问法是从概念切入，然后追问机制、工程取舍、失败排查和项目经验。本文按主题整理高频问题，并给出回答时应该覆盖的要点。

## 从问题约束到验证证据

一个稳定的技术回答可以按四层展开：

1. 先说明问题背景：这个方法为什么出现。
2. 再讲核心机制：输入、输出、关键公式或流程。
3. 接着讲优缺点：它解决什么，又牺牲什么。
4. 最后落到工程：如何评估、排查和上线。

面试官通常不是在找一句标准定义，而是在判断你能不能把概念放进真实系统里使用。

## 大模型基础

常见问题：

- 大模型、基础模型、LLM 有什么区别？
- 预训练、指令微调、偏好对齐分别做什么？
- 为什么下一个 token 预测能支持多种任务？
- 上下文窗口、token、temperature 分别影响什么？
- 模型幻觉产生的原因有哪些？

回答重点：不要把 LLM 描述成“数据库”。它是条件生成模型，擅长根据上下文组织语言和模式匹配，但事实准确性需要检索、工具或结构化数据支撑。

## Transformer 与 Attention

常见问题：

- Self-Attention 的 Q、K、V 分别是什么？
- 为什么要除以 `sqrt(d_k)`？
- Multi-Head Attention 的意义是什么？
- Transformer 为什么比 RNN 更适合并行训练？
- 位置编码解决什么问题？

回答重点：把张量形状说清楚。能讲出 `[seq_len, d_model]` 到 attention matrix 再到输出向量的过程，比背“注意力机制能关注重要信息”更有质量。

## RAG 与检索

常见问题：

- RAG 解决了 LLM 的哪些问题？
- 向量检索和关键词检索有什么区别？
- chunk 大小如何选择？
- RAG 答案不准怎么排查？
- 如何设计 RAG 评测集？

回答重点：把问题拆成检索和生成。先判断证据有没有被找出来，再判断模型有没有忠实使用证据。只说“调 prompt”通常不够。

## Agent 与工具调用

常见问题：

- Agent 和普通 Chatbot 的区别是什么？
- ReAct 的 Thought、Action、Observation 分别起什么作用？
- 工具调用如何做权限控制和失败恢复？
- 如何避免 Agent 无限循环？
- 什么任务不适合做成全自动 Agent？

回答重点：强调可控性。Agent 的亮点是多步执行，风险也来自多步执行。日志、权限、人工确认和退出条件都要说到。

## RLHF 与 PPO

常见问题：

- RLHF 的完整流程是什么？
- 奖励模型如何训练？
- PPO 为什么要限制策略更新幅度？
- KL 惩罚在 RLHF 中起什么作用？
- 奖励模型可能带来哪些偏差？

回答重点：RLHF 不是单个算法，而是一套数据、奖励、策略优化和评测流程。PPO 只是其中的策略更新方法之一。

## 项目追问

如果你做过 RAG、Agent 或微调项目，通常会被追问：

- 数据从哪里来？质量如何检查？
- 你用了哪些评测指标？有没有人工样例？
- 效果不好时排查顺序是什么？
- 延迟、成本、权限、安全怎么处理？
- 线上表现和离线评测是否一致？

项目回答要有证据：样例、指标、失败案例、改进前后对比。没有这些，项目听起来就会像课堂练习。

## 示例一：怎样回答“为什么 FlashAttention 更快”

先指出标准密集 Attention 的瓶颈不只是算术量：中间 N×N 矩阵在显存与高带宽内存之间反复搬运。再解释 FlashAttention 的 IO-aware 分块策略，将 Query、Key、Value 以适合片上缓存的方式处理，减少不必要的 HBM 读写。

随后讲清 Online Softmax 如何在不同块之间维护行最大值和归一化因子，保持精确 Attention 的数学形式。最后落到验证：比较不同序列长度、Head 维度与精度下的前向、反向时间和峰值显存，并注明硬件平台。

这比仅说“使用 Tile 和 Kernel Fusion，所以更快”更有技术解释力，因为它同时说明了优化对象、实现机制和验证方法。

## 示例二：怎样回答“RAG 准确率低怎么排查”

把系统拆为数据解析、召回、重排、上下文构造和答案生成。首先人工查看失败问题的正确证据是否存在于知识库；其次检查它是否进入检索 Top-k；再看 Rerank 后是否仍保留；最后确认生成模型收到证据后能否产生正确回答。

在面试中应提出具体指标：Recall@k 衡量相关证据覆盖，MRR 或 nDCG 衡量排序，答案正确率和引用一致性衡量生成质量。可补充 BM25、Dense、Hybrid 和 Hybrid+Rerank 的对照实验。

这套回答优于“重新调 Prompt”或“把 Top-k 加大”，因为它能定位失败模块，也能说明什么实验可以证明改进有效。

## 示例三：怎样回答“LoRA 为什么省资源”

先写出权重更新 ΔW=BA，其中 A 与 B 是秩为 r 的两个矩阵。指出可训练参数从 d_out×d_in 降至 r(d_in+d_out)，用 4096×4096、r=8 的例子可算出 65536 个增量参数，仅约为原权重的 0.39%。

然后区分可训练参数、优化器状态和完整模型显存：基础权重仍在，因此整体显存不会随训练参数比例同比缩减。最后说明目标模块、秩、训练预算和任务效果需要共同评估。

这种回答既有公式也有部署判断，比“LoRA 用低秩分解所以成本低”更完整。


## 技术表达的典型失误

第一，堆概念。面试里连续说一串术语，但没有机制和例子，通常会被继续追问。

第二，只讲模型效果，不讲数据和评测。大模型项目的质量很大程度取决于数据流和评测闭环。

第三，把所有问题都归因于模型不够强。很多线上问题来自文档解析、检索、工具权限、提示词版本和业务规则。

## 延伸阅读与答题路径

建议按本站路线先补齐 LLM、Tokenizer、Attention，再看 RAG、Agent 和 PPO。面试准备不是背题库，而是把这些主题连成一张能复述、能排查、能落地的知识网。
